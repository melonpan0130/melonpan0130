--- title: "LLM 모델 파일의 정체는?" date: "2026-11-06" ---

LLM(대규모 언어 모델)의 정체는 결국 거대한 '데이터 파일'이다.

정확히는 모델이 학습한 숫자(가중치)를 담은 큰 파일과, 그 숫자를 어떻게 읽어야 하는지 알려 주는 몇 가지 설정 파일의 묶음이다.

LLM을 쓴다는 것은 이 파일들을 서버나 PC에 복사(설치)한 뒤, 이를 읽어 들이는 실행 프로그램(추론 엔진)으로 돌리는 것이다.


1. LLM 모델 파일이란 무엇인가?

  • 수십억~수천억 개의 숫자(파라미터/Weights)가 저장된 거대한 데이터 파일 (일부 초대형 모델은 조 단위)

  • 구성: 가중치 파일만으로는 부족하고, 모델 구조를 적은 설정 파일(config.json)과 텍스트를 토큰으로 바꾸는 토크나이저 파일이 함께 필요하다.

    • 토크나이저 파일은 사람의 글자와 모델이 알아듣는 숫자를 서로 바꿔 주는 '통역 사전'이다.
      • 모델은 숫자만 계산할 수 있어서, 텍스트를 잘게 자른 조각(토큰)마다 번호를 붙여 숫자로 바꿔 넣어야 한다. (예: "안녕하세요" → ["안녕", "하세요"] → [15234, 8821], 번호는 설명용 예시)
      • 모델이 내놓은 숫자도 토크나이저로 다시 글자로 바꿔야 답변이 된다.
      • 파일 안에는 어떤 조각이 몇 번인지 적은 어휘 목록(vocab), 텍스트를 자르는 규칙, '대화 시작'·'답변 끝' 같은 신호용 특수 토큰이 들어 있다. (보통 tokenizer.json, tokenizer_config.json 같은 이름)
      • 토크나이저는 모델과 짝이 맞아야 한다. 모델은 학습할 때 정해진 번호 약속으로 배웠기 때문에, 다른 모델의 토크나이저를 쓰면 번호의 뜻이 달라져 엉뚱한 답이 나온다.
    • .gguf 형식은 이 모든 것을 파일 하나에 묶어 둔 형태다.

  • 파일 확장자

    • .safetensors: 현재 가장 널리 쓰이는 표준 형식
    • .bin: 예전 PyTorch 형식. 파일을 열 때 임의 코드가 실행될 수 있는 보안 문제가 있어 .safetensors로 대체되는 추세
    • .gguf: llama.cpp·Ollama 계열에서 쓰는 단일 파일 형식. 주로 양자화 모델 배포에 쓰이지만, 양자화하지 않은 버전(F16 등)도 있다.
    • 양자화(Quantization) 기법을 적용하면 14GB짜리 7B 모델(FP16 기준)을 4GB 수준으로 압축해서 일반 PC에서도 돌릴 수 있다.
  • 크기: 모델의 크기(파라미터 수)에 따라 파일 용량이 매우 크다.
    • 예: 7B(70억 파라미터) 모델은 약 4GB~14GB
    • 예: 70B(700억 파라미터) 모델은 약 40GB~140GB 이상

비유하자면,

  • LLM 모델 파일은 '뇌'에 해당한다.
  • 이 파일 안에는 '어떤 단어(토큰) 뒤에 어떤 단어가 올지'를 판단하는 데 쓰이는 수학적 패턴이 담겨 있다.
    • 실제로는 확률표가 저장되어 있는 것이 아니라, 입력이 들어오면 다음 토큰의 확률을 계산해 내는 숫자(가중치)들이 저장되어 있다.
  • 이 파일만으로는 아무것도 하지 못한다.
  • '뇌'만 따로 떼어놓은 상태이므로, 이 뇌를 처리할 수 있는 '몸체(추론 엔진)'가 필요하다.

2. 추론 엔진이란 어떤 '파일'인가?


추론 엔진 (Inference Engine)은 모델 파일(뇌)을 읽어들이고, 사용자가 입력한 텍스트를 처리하여 답변을 생성하는 소프트웨어이다.

  • 실행 가능한 소프트웨어(Executable) 또는 라이브러리

  • 배포 형태

    • 같은 엔진도 여러 형태로 배포된다.
    • 실행 파일 (Binary): Ollama, llama.cpp의 컴파일된 바이너리 등. 운영체제(Windows/Linux)에서 직접 실행되는 프로그램
    • 라이브러리 (Library): Python의 vLLM 패키지, llama.cpp의 C/C++ 라이브러리 등. 개발자가 코드를 작성하여 호출하는 소프트웨어 부품
    • 컨테이너 이미지 (Docker Image): vLLM, SGLang 등은 Docker 이미지로도 많이 배포되어, 서버에서 격리된 환경으로 실행

  • 참고: Hugging Face transformers

    • 추론 전용 엔진이라기보다, 모델을 불러와 학습과 추론을 모두 할 수 있는 범용 모델 라이브러리다.
    • transformers만으로도 추론은 가능하지만, 여러 요청을 빠르게 처리해야 하는 운영 환경에서는 메모리 관리와 배칭이 최적화된 vLLM·SGLang 같은 전용 추론 엔진을 주로 쓴다.

  • 역할

    • 모델 파일(Weights)을 메모리(RAM/GPU VRAM)에 올린다.
    • 사용자가 입력한 텍스트를 토큰으로 바꾸고, 다음 토큰을 하나씩 계산해 이어 붙인다.
    • 생성된 답변을 출력한다.
    • 추론 엔진은 모델 파일을 "실행"시키는 런타임(Runtime) 역할을 한다.

3. LLM을 '설치'하고 실행하는 과정


LLM을 로컬(내 컴퓨터나 사내 서버)에서 돌리려면 LLM 모델 파일, 추론엔진 파일이 필요하다.

  1. 추론 엔진 설치: (예: Ollama 설치)
  2. 모델 다운로드/복사: (예: ollama pull llama3 명령어 실행, 또는 Hugging Face Hub 같은 모델 공유 사이트에서 모델 파일 다운로드)
    • 이 단계에서 모델 파일이 내 컴퓨터의 특정 폴더(예: Windows의 Ollama는 C:\Users\사용자명\.ollama\models)에 저장된다.
  3. 실행: 엔진이 모델 파일을 메모리에 로드하면, 이제 사용자의 질문에 답변할 수 있다. (Ollama는 첫 질문이 들어올 때 모델을 로드한다.)

4. API 방식과 셀프 호스팅의 차이 (파일 관점에서)


먼저 짚을 점: '어떤 모델이냐'와 '어디서 실행하느냐'는 별개의 문제다.

  • ChatGPT(GPT), Claude 같은 모델은 가중치 파일이 공개되지 않아(closed), 벤더의 서비스를 통해서만 쓸 수 있다.
  • Llama, Mistral, Qwen 같은 모델은 가중치 파일이 공개되어(open-weight), 직접 받아서 돌릴 수도 있고 클라우드 API로 쓸 수도 있다.

  • API 방식
    • 벤더 서버에서 실행, 흔히 클라우드 LLM이라고 부른다.
    • 모델 파일은 벤더(OpenAI, Anthropic 등)의 서버에 저장되어 있다.
    • 우리는 파일을 설치하지 않고, 인터넷을 통해 벤더의 서버에 요청을 보내고 답변을 받아온다.
    • 따라서 내 컴퓨터에는 모델 파일이 없으며, 인터넷 연결이 필수이다.
  • 셀프 호스팅
    • 내 컴퓨터·사내 서버에서 실행, 흔히 로컬 LLM이라고 부름, 오픈 웨이트 모델만 가능하다.
    • 모델 파일이 내 컴퓨터나 사내 서버에 저장되어 있다.
    • 모델 파일을 한 번 받아 두면, 인터넷 연결 없이도 내 하드웨어(CPU/GPU)로 모델 파일을 직접 처리한다.
    • 입력한 데이터가 외부로 전송되지 않고, 인터넷이 끊겨도 작동한다. (대신 보안 관리 책임은 내 쪽에 있다.)
    • 큰 모델일수록 고성능 GPU(그래픽 카드)와 많은 저장 공간·메모리가 필요하다. 작은 양자화 모델은 일반 PC나 노트북에서도 돌아간다.
    • 오픈 웨이트 모델이라도 라이선스에 사용 조건이 붙어 있을 수 있으니 확인이 필요하다.

LLM 모델은 "설치"보다는 "모델 파일을 내 환경에 가져와서 실행 엔진에 연결하는 과정"에 가깝다.

모델 파일(뇌)과 추론 엔진(몸)이 내 서버에 함께 있는 한, 그 AI는 내 서버 위에서 돌아가게 되는 것이다.
